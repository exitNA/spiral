# Ethos 验证记录

日期：2026-09-06。场景定义见 [scenarios.json](scenarios.json)，执行与评分边界见 [README.md](README.md)。

## 本次协议变更

移除 Ethos 的 UserPromptSubmit 与 Stop Hook。自动发现依赖安装后的 Skill 隐式选择，已选技能在正常任务最终回答前完成筛选；不再每轮注入提示或阻止结束来启动学习专用续跑。不保证每轮都观察到学习信号。

## 历史结果的边界

此前记录的 12 项自动测试包含 7 项旧 Hook 进程测试与 5 项 Loop 测试。旧 Hook 测试覆盖一次 Stop 阻止、续跑退出等协议行为，未验证主对话是否出现额外反馈、上下文噪声及不必要续跑。把进程正常结束当成学习机制无干扰的证据是不充分的；这些结果不能证明本次实现通过。

此前明确纠正、临时偏好、任务末尾证据及跨会话候选等实验属于旧版本的行为观察。部分实验直接提供 Skill 路径，仅证明技能与磁盘证据链，不能证明新版安装后的隐式选择。旧安装指纹、Hook 信任状态及 Windows Hook 测试不适用于当前实现。

## 本次实际验证

- 仓库校验、官方 Skill 与插件校验、5 项现存 Loop 回归以及差异空白检查通过；Gitleaks 扫描未发现泄露。旧 Hook 测试及对应 Windows CI 作业已删除。
- 独立只读评审确认无剩余 Hook 注册、脚本引用或强制续跑要求。校验器约束 Ethos 不得通过 manifest 或默认目录注册生命周期 Hook。
- 本机两个旧 Ethos Hook 已逐项停用；安装 `0.1.0+codex.20260906073726`，安装目录无 hooks，技能正文与源码一致。源码发布版本保持 `0.1.0`。
- Codex CLI 0.153.0 使用用户默认模型，在两个隔离临时 Git 仓库执行真实请求，没有显式调用 `$ethos`，没有注入测试评分标准。
- 普通请求“只回答：收到。”：事件输出只有一次 turn.started、一次 turn.completed、一个 agent_message“收到。”；没有工具调用、hook_prompt 或学习专用追加回答。
- 明确长期原则请求：自动读取安装版 Ethos，将最少信息收集原则和履约例外写入 SOUL，回答公司与职位默认不收集。事件输出只有一次 turn.started、一次 turn.completed；正常进度消息及最终回答共三个 agent_message，没有 hook_prompt 或学习专用续跑。
- 两次进程均正常退出。事件输出与安装目录无 Hook 的检查共同支持本次无重复注入结论；单独统计 turn 数不足以排除同一轮内的续跑。

发布级重复行为实验、隐式选择可靠性、跨会话场景及只读行为仍须按执行指南记录实际结果。结构检查与行为证据不能相互替代。
